### `playlist_schema.json`

This JSON defines a schema for a playlist file generated by Nokia 220 4g 2024 model software when
manually creating a playlist in the phone.

The playlist file created is a binary file containing various entries.
Each entry is a block of pre-defined number of bytes containing hex-code of
pre-identified values.

The schema defined in this JSON file is defined based on the playlist file
analysis documented under `Analysis/For_Playlists_Index_File` folder.

Note:

  * The contents of this file are defined based on analysis done on
    phone generated files. So until the analysis becomes outdated, it
    is not recommended to be changed by users wanting to use this utility.

### `playlist_schema_values.json`

This JSON defines values to be used for data specified in `playlist_schema.json`.
The chunks data for a data are based on the analysis documented under `Analysis/For_Playlist_File` folder.

Note:

  * The contents of this file are defined based on analysis done on
    phone generated files. So until the analysis becomes outdated, it
    is not recommended to be changed by users wanting to use this utility.

### `playlists_index_schema.json`

This JSON defines a schema for a playlists index file generated by Nokia 220 4g 2024 model software. When
manually creating a playlist in the phone its information gets appended in this index file.

The playlists index file created is a binary file containing various entries.
Each entry is a block of pre-defined number of bytes containing hex-code of
pre-identified values.

The schema defined in this JSON file is based on the analysis documented
under `Analysis/For_Playlists_Index_File` folder.

To start with refer `readme.txt` and `decoding_ending_bytes.txt` files under that folder.

### `playlists_index_schema_values.json`

This JSON defines values to be used for data specified in `playlists_index_schema.json`.

This file defines data for chunks for `header_entry` schema defined in `playlists_index_schema.json`.
For e.g. the data set against `header_entry['chunks_data']['1'] refers
to the data to be used by the 1st chunk of the header entry to be created.
This data was found from the analysis documented under `Analysis/For_Playlists_Index_File`.

This file defines values for default-created playlists and user-created playlists separately.

For a particular playlist's entry the data is set through the playlist number. For e.g.
the data set against `default_playlists['5']['playlist_entry']['1']` refers
to the data to be used while creating entry for 1st playlist in the default 5 playlists.

For playlists entry having identical data it is set through `unmentioned` key. For e.g.
the data set against `default_playlists['5']['playlist_entry']['unmentioned']` refers
to the data to be used by entry to be created for default-playlist number 2, 3 and 4.

For last-playlist data is set through `last_playlist_entry` key. For e.g.
the data set against `default_playlists['5']['last_playlist_entry'] refers
to the data to be used for entry to be created for default-playlist number 5.

The `chunks_data` against a playlist entry's data maps a chunk's number to chunk's value.
For more details refer the analysis documented under `Analysis/For_Playlists_Index_File` folder.
To start with refer `readme.txt` and `decoding_ending_bytes.txt` files under that folder.

Based on the number of playlists available, value for the chunks of a particular playlist's
entry gets set by the phone software. All these values are noted in the analysis file
'Analysis/For_Playlists_Index_File/decoding_ending_bytes.txt'.

The 4th chunk in `playlist_entry['chunks']` schema defined in `playlists_index_schema.json`,
refers to the 5th byte whose values are noted in the referenced analysis file.

Similarly the 6th chunk in `playlist_entry['chunks']` schema defined in `playlists_index_schema.json`,
refers to the 13th byte whose values are noted in the referenced analysis file.

The 4th chunk in `last_playlist_entry['chunks']` schema defined in `playlists_index_schema.json`,
refers to the 5th byte whose values are noted in the referenced analysis file.

Note:
  When user created playlists are available, then for the last one in them
  6th chunk is NA but for default last playlist that chunk is APPLICABLE.
  For more details refer section "user created playlists 1" under
  referenced analysis file.

  And this playlists index generator utility is meant to be used for
  creating entries for user-created playlists. If they itself
  will not be available, then there is no point in using this utility.
  So the chunk values noted under section "for user created playlists 0"
  under reference analysis file, is really not applicable when
  this utility is to be used.

The playlists entries data are defined based on number of
default-created playlists and user-created playlists.

For e.g. `default_playlists['5']` refers to data to be used when there are
5 default playlists available.

From the analysis documented under `Analysis/For_Playlists_Index_File` folder
it was found that by default Nokia phone model's software creates 5
default playlists. Thus the data for default-playlists is defined accordingly.

User-created playlists cannot be fixed. But based on the analysis documented
under `Analysis/For_Playlists_Index_File` folder it was found that for
particular number of user-created playlists few of the chunks data for few of the
playlists entries were different and remaining ones had identical data for those
chunks.

For e.g. `user_created_playlists['3']` refers to data to be used when there are
3 user-created playlists available.

Similarly `user_created_playlists['4']` refers to data to be used when there are
4 user-created playlists available.

Similarly `user_created_playlists['> 7']` refers to data to be used when there are
more than 7 user-created playlists available.

Similarly `user_created_playlists['>= 13']` refers to data to be used when there are
13 or more user-created playlists available.

For number of user-created playlists not mentioned specifically the data for
entries for those playlists is defined through `user_created_playlists['unmentioned']`.

Note:

  * The contents of this file are defined based on analysis done on
    phone generated files. So until the analysis becomes outdated, it
    is not recommended to be changed by users wanting to use this utility.
