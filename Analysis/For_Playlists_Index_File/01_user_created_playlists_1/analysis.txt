Following is the analysis for playlists index file named `listinfo.data` containing 1 user-created playlist on phone.
The hex-dump of that file can be found in `hex_dump.txt` in this file's folder.


------

Based on the analysis done for `listinfo.data` containing entries for 3 and 4 user-created playlists (refer `analysis.txt`
in `Analysis/For_Playlists_Index_File/03_user_created_playlists_three` and `Analysis/For_Playlists_Index_File/03_user_created_playlists_four`
folders

we will investigate only the last two entries because

all entries except last should occupy 532 bytes.
last-entry should contain 524 bytes.

~~~~~~~~~~~

Fifth entry starts in 61st row at 4th byte (offset 0x873) and ends in 75th row at 31st byte (offset 0xA86).
Sixth entry starts in 75th row at 32nd byte (offset 0xA87) and ends in 90th row at 15th byte (offset 0xC92).

~~~~~~~~~~~~~~

Let's subtract the hex offsets to find the occupied bytes.

Fourth entry:
  A86 - 873 = 213 = 531 in decimal. Because of subtraction we loose one count so include it back. So that becomes 532 bytes.

Fifth entry:
  C92 - A87 = 20B = 523 in decimal. Adding back the one count we get 524 bytes.

~~~~~~~~~~~~~

Let's consider the ending bytes for all the entries. We will consider from the one which doesn't start with 00 byte
and goes upto the last byte for that entry.

Based on the previous analysis for `listinfo.data` containing entries for 3 and 4 user-created playlists

for all entries except last we should have 20 ending bytes
for last entry we should 12 ending bytes

  1b 00 00 00 00 00 00 00 00 00 00 00 02 00 00 00 00 00 00 00

For fifth entry following are the bytes

~~~~~~~~~~~~~

Based on the previous analysis for `listinfo.data` containing entries for 3 and 4 user-created playlists
